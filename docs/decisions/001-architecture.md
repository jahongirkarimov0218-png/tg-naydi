# ADR-001: Архитектура TG Naydi для Vercel и разделение решений

**Статус:** Утверждено владельцем продукта (2026-11-20, Checkpoint 1)
**Дата:** 2026-11-20
**Для кого написано:** Для нетехнического основателя (простым языком, без скрытых бизнес-рисков).

---

## 1. Главная проблема, которую решает эта архитектура

На скриншотах пользователь загружает `contacts.csv` (до 5 000+ номеров), нажимает «Запустить», может остановить и продолжить проверку, и получает `result.csv` с `username` и типом (`человек` / `канал`).

Из официальной документации Vercel и Telegram вытекают **3 жёстких технических ограничения**, которые нельзя игнорировать:

1. **Лимит Vercel на размер запроса — 4.5 MB (`413 FUNCTION_PAYLOAD_TOO_LARGE`).**
   Если загружать тяжёлый CSV напрямую в API Vercel, запрос упадёт.
   - *Решение:* браузер сам разбирает CSV (`papaparse`), очищает и нормализует номера (`libphonenumber-js`) и отправляет на сервер маленькими пачками по 500 номеров (~25 KB на запрос).
2. **Лимит Vercel на время работы и отсутствие постоянного диска.**
   На бесплатном плане Vercel Hobby функция живёт максимум 300 секунд (Fluid Compute), а временные файлы стираются между перезапусками. Если хранить прогресс «в памяти сервера», после обновления страницы (`F5`) база из 5 000 номеров исчезнет.
   - *Решение:* состояние каждой задачи хранится во внешнем хранилище с автоудалением через 24 часа (`Upstash Redis` на Vercel — бесплатный тариф; локально и в автотестах — файловое хранилище `.data/jobs/`). Проверка идёт короткими атомарными шагами (по 1 пачке за шаг), поэтому **Пауза → F5 → Продолжить** сохраняет прогресс гарантированно.
3. **Telegram Bot API не умеет искать людей по номеру телефона.**
   Для реальной проверки нужен клиентский протокол **Telegram MTProto** (`contacts.importContacts` / `contacts.resolvePhone` + `users.getFullUser` для `personal_channel_id`) с отдельным пользовательским Telegram-аккаунтом. Telegram жёстко ограничивает частоту (`FLOOD_WAIT`) и скрывает людей с приватным номером.
   - *Решение (Порты и Адаптеры):* логика проверки вынесена за единый интерфейс `TelegramLookupProvider`:
     - **`SandboxLookupProvider`** — работает сразу на Vercel и в автотестах. Воспроизводит реальные задержки, паузы, `FLOOD_WAIT`, скрытые номера, людей и каналы **без риска бана** аккаунта. В интерфейсе и в `result.csv` **честно и заметно** помечен как `ДЕМО-РЕЖИМ (SANDBOX)`, чтобы никто не перепутал тест с живой проверкой.
     - **`MtprotoLookupProvider` (GramJS)** + отдельный воркер `worker/mtproto.ts` — реальный адаптер Telegram, который подключается к той же базе задач, как только ты укажешь свои `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` и `TELEGRAM_SESSION`. Он строго соблюдает паузы, уважает `FLOOD_WAIT` и сразу удаляет импортированный контакт (`contacts.deleteContacts`), чтобы не засорять книгу.

## 2. Выбранный стек и стоимость в месяц (приоритет: старт за \$0)

| Слой | Выбор | Почему именно это | Стоимость на старте |
| :--- | :--- | :--- | :--- |
| Веб-приложение (UI + API) | **Next.js (App Router) + TypeScript + Tailwind CSS** | Нативная платформа для Vercel, единый код фронта и API, быстрый деплой и откат одной командой | **\$0 / мес** (Vercel Hobby) |
| Разбор CSV и телефонов | **`papaparse` + `libphonenumber-js`** | Автоматически понимает `,` и `;` из Excel, кодировку Windows-1251/UTF-8 и любые форматы номеров (`8 905...`, `+7...`, `+998...`) | **\$0** (open-source) |
| Хранилище задач (переживает F5) | **`JobStore`: Upstash Redis (Vercel) + FileStore (локально/CI)** | Работает по HTTP без проблем с коннектами в serverless, встроенное автоудаление данных через 24 часа (TTL). На Vercel без настроенного Upstash сервис честно предупреждает и не имитирует сохранение в `/tmp`. | **\$0 / мес** (Upstash Free: до 500k запросов/мес) |
| Проверка Telegram | **`SandboxLookupProvider` (внутри Vercel `/step`) + отдельный воркер `worker/mtproto.ts` (GramJS)** | Безопасный пилот и CI сегодня + готовый переход в боевую работу без переписывания сайта; в живом режиме включён ключ оператора (`OPERATOR_ACCESS_KEY`) и очередь по 1 задаче (FIFO), чтобы посторонние не забанили аккаунт | **\$0** локально или **\$4–5/мес** за минимальный VPS под 24/7 воркер |
| Автотесты и CI | **`Vitest` + `Playwright` + GitHub Actions (Linux) + `gitleaks`** | Реальная проверка в браузере и защита от утечки секретов на Linux-раннере | **\$0 / мес** (GitHub Free) |

## 3. Что сломается при росте (честное предупреждение заранее)

1. **При базе > 10 000 номеров в одной задаче** в бесплатном Upstash Redis упрёмся в размер одного JSON-объекта или лимит 500k команд в месяц → потребуется переход на **Neon Postgres / Supabase** (благодаря интерфейсу `JobStore` это замена одного адаптера без переделки UI).
2. **При активной живой проверке через 1 Telegram-аккаунт** Telegram начнёт выдавать `FLOOD_WAIT` (паузы от минут до часов) — ускорять запросы поверх лимитов запрещено (аккаунт забанят). Для больших коммерческих объёмов понадобится легальный пул выделенных аккаунтов и соблюдение лимитов Telegram.
3. **На текущей Windows-машине** нет WSL2/Docker, поэтому локальная песочница ОС `bubblewrap` недоступна. Локальные запреты держат `PreToolUse`-хуки, а полная Linux-проверка идёт в GitHub Actions.

## 4. Граница ответственности: что решил инженер vs что утверждает основатель

| Вопрос | Кто решает | Решение |
| :--- | :--- | :--- |
| Фреймворк, библиотеки парсинга, структура API, формат `JobStore`, тесты, хуки | **Инженер (решено)** | Next.js + `papaparse` + `libphonenumber-js` + Upstash/FileStore + Vitest/Playwright + хуки `exit 2`. |
| Как определяется тип «канал» vs «человек» | **Основатель утверждает (предложение инженера)** | В Telegram по номеру находится аккаунт пользователя. Если к профилю привязан публичный личный канал (`personal_channel_id`), классифицируем как `канал` (и отдельно сохраняем личный `@username` в колонке `personal_username` если есть), иначе — `человек`. |
| Честный режим первого деплоя на Vercel | **Основатель утверждает (предложение инженера)** | Первый релиз на Vercel стартует в явно помеченном **`ДЕМО-РЕЖИМЕ (SANDBOX)`** (безопасен, работает сразу, не требует твоих Telegram-ключей) + готовый `worker/mtproto.ts` с пошаговой инструкцией подключения живого аккаунта в 3 шага. |
| Хранение телефонов клиентов (PII) | **Основатель утверждает (предложение инженера)** | Номера в интерфейсе маскируются (`+7 905 •••-45-67`), полная база доступна только по секретному токену задачи, автоматически удаляется через **24 часа** и может быть удалена кнопкой мгновенно. |
| Авторизация GitHub / Vercel для живого деплоя | **Основатель (Точка №2)** | Однократный вход `gh auth login` и `vercel login` на этапе деплоя. |
