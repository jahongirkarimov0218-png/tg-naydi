## 1. Источник истины (Single Source of Truth)

Для минимизации рассинхронизации при старте проекта **Git-репозиторий** (`d:\tg naydi`, ветка `main`) назначается единственным источником истины для всех артефактов разработки:

| Артефакт | Место хранения в Git | Кто обновляет | Кто утверждает переход |
| :--- | :--- | :--- | :--- |
| Постановка (Intent) | `docs/sdlc/intent.md` | Агент по запросу основателя | Владелец продукта |
| Спецификация (Spec) | `docs/sdlc/spec.md` | Агент | Владелец продукта |
| Архитектурные решения (ADR) | `docs/decisions/NNN-*.md` | Агент (простым языком) | Владелец продукта (бизнес-риски) |
| План реализации (Plan) | `docs/sdlc/plan.md` | Агент (до написания кода) | Инженер / ответственный за реализацию |
| Контекст и навыки агента | `CLAUDE.md`, `.claude/skills/*/SKILL.md` | Агент (через PR/ревью) | Владелец кода |
| Правила проверки кода | `REVIEW.md` | Агент + владелец кода | Владелец кода |
| Технические барьеры | `.claude/settings.json`, `scripts/hooks/*`, `.github/workflows/*` | Агент | Проверка тестами + CI |
| Инциденты / новые постановки | `docs/sdlc/incidents/intent-INC-*.md` | Детерминированный детектор аномалий | Владелец продукта / сервиса |

> **Связь с внешними системами:** при подключении GitHub Issues / PR идентификатор задачи фиксируется в заголовках коммитов и артефактов, а SHA коммита — в описании PR. Отдельный трекер (Jira/Linear) на старте не вводится, чтобы исключить режим двух конкурирующих источников истины.

## 2. Аудит реальной среды выполнения (сырые факты на 2026-11-20)

| Компонент | Фактическое состояние на машине | Влияние на SDLC и компенсация |
| :--- | :--- | :--- |
| Репозиторий `d:\tg naydi` | Инициализирован с нуля (`greenfield`, 0 исторических PR) | Нет 30–90-дневной истории PR/багов; фиксируем стартовый baseline с коммита `0`, eval-набор собираем из 12+ реальных кейсов предметной области. |
| Git | `2.54.0.windows.1` | Полная поддержка `git worktree` и веток. |
| Node / Пакетный менеджер | `Node v20.20.2`, `pnpm 12.18.0` (`npm`/`npx` отсутствуют) | Все команды сборки, тестов и CLI (`vercel`, `playwright`) запускаются строго через `pnpm` / `pnpm dlx`. |
| Python / Pytest | `Python 3.13.17`, `pytest` установлен | Используется для кроссплатформенных `PreToolUse` хуков и при необходимости скриптов проверок. |
| Claude Code CLI | `2.1.283`, **`loggedIn: false`** | Хуки и `.claude/settings.json` валидируем по официальной схеме `code.claude.com` и прогоняем напрямую реальными JSON-событиями через `stdin` (проверка `exit 2`). Для `claude -p` A/B eval требуется авторизация `claude auth login` либо независимый изолированный агентский прогон (фиксируется честно без подмены). |
| GitHub CLI (`gh`) | Установлен, **не авторизован** | Для создания удалённого репозитория, PR и Branch Protection потребуется однократный `gh auth login` (Точка участия основателя №2). |
| Vercel CLI | Не установлен глобально | Используем `pnpm dlx vercel` после авторизации (Точка участия основателя №2). |
| Изоляция ОС (Sandbox) | **Windows + WSL1 (Ubuntu Stopped), Docker отсутствует** | Нативная песочница Claude Code (`bubblewrap`) **не работает** на нативном Windows и WSL1 (требует Linux/WSL2). **Честная компенсация:** локально запреты держат `PreToolUse` хуки (`exit 2`) и `permissions.deny`; полная Linux-изоляция и сканер секретов `gitleaks` принудительно исполняются в GitHub Actions (`ubuntu-latest`). Переход на WSL2/Docker зафиксирован как рекомендация при масштабировании. |
