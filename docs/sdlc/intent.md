# Stage 02 — Постановка задачи (intent.md)

**ID инициативы:** `TGN-001`
**Дата:** 2026-11-20
**Инициатор / Владелец продукта:** Основатель (нетехнический владелец продукта)
**Статус:** Черновик на утверждение владельцем продукта

---

## 1. Проблема (факты от основателя)

Владельцы CRM-баз, отделы продаж, лидогенераторы и агентства имеют списки телефонных номеров своих клиентов, заявок и партнёров (в разных форматах, обычно в CSV/Excel). Писать контактам в Telegram напрямую по номеру телефона неудобно: выше риск ошибок и ограничений со стороны Telegram, плюс заранее непонятно, у кого есть открытый `@username` и является ли контакт живым человеком или каналом.

Нужен простой веб-сервис, куда можно загрузить свой файл с телефонами, запустить аккуратную пакетную проверку с паузами и возможностью остановить/продолжить прогон, а на выходе скачать готовый `result.csv` с `username` и типом аккаунта.

---

## 2. Предлагаемый результат

Веб-платформа **TG Naydi**, развёрнутая на публичном URL на **Vercel**, которая реализует сквозной пользовательский путь со скриншотов:
1. Пользователь загружает CSV/TXT со своей базой номеров (любой формат номеров, кодировка UTF-8 или Windows-1251, разделитель `,` или `;`) — или нажимает «Загрузить пример» для мгновенной проверки работы.
2. Запускает проверку пачками с настраиваемой паузой; в реальном времени видит ход проверки в тёмном мониторе (`база.csv • проверяем`) с маскировкой номеров (`+7 905 •••-45-67`) и прогресс (`X из Y`).
3. Может нажать **Пауза**, перезагрузить страницу (`F5`) и нажать **Продолжить** без потери прогресса.
4. По завершении (или на паузе) видит итоговую сводку (`найден username`, `человек, пиши`, `канал`), список найденных `@username` с метками типа и скачивает `result.csv`, который без искажения кириллицы открывается в Excel.
5. Вся разработка, защита от ошибок и деплой на Vercel выстроены по полному циклу **AI-native SDLC** с проверяемыми техническими барьерами, откатом и тестами.

## 3. Затронутые пользователи и системы

- **Пользователи:**
  - Специалисты по Telegram-рассылкам (по собственной базе клиентов/уведомлений).
  - Команды лидогенерации и продаж / аутрича.
  - Маркетинговые агентства (подготовка баз для клиентов).
  - Владелец продукта (не-программист), которому нужны понятные проверки, прозрачный режим работы и простой откат релиза.
- **Системы:**
  - Веб-приложение Next.js на **Vercel**.
  - Хранилище состояния задач (**Upstash Redis** в облаке Vercel / локальный **FileJobStore** в разработке и CI).
  - Модуль проверки Telegram (**`SandboxLookupProvider`** для безопасного пилота/тестов + готовый **`MtprotoLookupProvider`** на GramJS для живого отдельного Telegram-аккаунта).
  - Репозиторий Git + GitHub Actions CI + локальные `PreToolUse`-хуки Claude Code.

## 4. Факты основателя vs Предположения инженера (явное разделение)

### Подтверждённые факты от основателя (из 2 скриншотов и сообщений)
- Целевой сценарий: 3 шага (`загрузить файл → запустить проверку пачками с паузами и паузой/продолжением → скачать result.csv с username и типом`).
- Целевой масштаб из примера на скриншоте: до 5 000 номеров в файле.
- В интерфейсе номера маскируются (`+7 905 •••-45-67`), в итогах показываются счётчики (`найден username`, `человек, пиши`, `канал`) и список `@username` с цветными метками (`человек` / `канал`).
- Целевой хостинг: **Vercel**.
- Основатель — не программист, технические решения делегированы инженеру с требованием максимального качества и честности (без подмены реального продукта заглушкой).

### Инженерные предположения (требуют подтверждения или корректировки владельцем продукта)
1. **Стартовый провайдер на Vercel:** на первом публичном деплое по умолчанию включён честно промаркированный **`ДЕМО-РЕЖИМ (SANDBOX)`** (чтобы сервис сразу работал без передачи твоих личных Telegram-ключей и без риска бана аккаунта), а живой `GramJS MTProto`-воркер лежит в репозитории готовым к подключению по инструкции.
2. **Определение типа «канал»:** так как Telegram по номеру телефона возвращает профиль пользователя, типом `канал` считаем профиль, у которого привязан публичный личный канал (`userFull.personal_channel_id` с `@username`). Разбор ссылок из текстового bio намеренно не делаем в MVP (избегаем ложных срабатываний и лишних запросов, повышающих риск `FLOOD_WAIT`).
3. **Честный статус «не найден / скрыт»:** Telegram намеренно не позволяет программно отличить незарегистрированный номер от номера с закрытой приватностью («Кто может найти меня по номеру»). Поэтому и в `SANDBOX`, и в `LIVE_MTPROTO` используется один честный статус `не найден / скрыт` (`not_found_or_hidden`).
4. **Защита персональных данных (PII), доступ оператора и соблюдение правил Telegram:** сервис предназначен только для собственной базы клиента, никогда не обходит `FLOOD_WAIT` / приватность Telegram и удаляет загруженные базы автоматически через **24 часа**. В `SANDBOX`-режиме доступ к задаче защищён криптографическим токеном; при включении `LIVE_MTPROTO` на публичном сайте дополнительно включается ключ оператора (`OPERATOR_ACCESS_KEY`) и глобальная очередь по 1 задаче, чтобы посторонние не могли заблокировать Telegram-аккаунт владельца.
5. **Базовая страна для коротких номеров без кода:** по умолчанию `RU` (`+7`, так как примеры на скриншотах российские — `+7 905...`, Казань), с возможностью переключить в интерфейсе (например, `UZ` `+998`) и автоматическим распознаванием любых международных номеров с `+`.

## 5. Ограничения

- **Безопасность и PII:** никаких реальных номеров, `.env` или Telegram-сессий в Git и логах сервера; строгая блокировка через хуки и `gitleaks`.
- **Лимиты платформы:** обход лимита 4.5 MB Vercel через чанковую отправку нормализованных номеров; сохранение состояния вне оперативной памяти serverless-функции.
- **Честность режима:** невозможность выдать сгенерированные в `SANDBOX` username за живые данные Telegram (явный баннер в UI + колонка `mode` в `result.csv`).
- **Бюджет старта:** \$0/мес для веб-части и CI (бесплатные тарифы Vercel Hobby, Upstash Redis Free, GitHub Free).
